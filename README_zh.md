# EviLoom：长视频问答的证据选择器

EviLoom 是项目中原 `PERD-v2` 的正式公开名称。名字来自“把长视频中分散的证据织成可供模型理解的局部证据包”。它是当前最适合作为项目主线的版本：并非每个开发子集上都最高，但它是唯一完成 Video-MME、LongVideoBench、MLVU、LVBench 四个全量数据集验证的高级版本，证据比只跑过 4×300 开发集的后续方法更完整。

## 方法用人话怎么理解

Top-K 只会拿分数最高的 32 帧，很容易在同一小段里连续拿到很多相似画面。EviLoom 不把每帧看成互不相关的点，而把整段视频看成一条“证据分布”：哪里与问题相关，哪里就有证据需求。选到一帧后，它同时认为附近内容相似的帧已经得到部分覆盖，于是下一步更愿意去尚未覆盖的证据峰。

在问题明确出现 first、last、before、after、again 等时间关系时，EviLoom还会建立独立的时间证据通道。Planner可以提出目标和参考事件，但不能看选项、猜答案或枚举颜色/形状；提出的查询只有在检索峰足够可靠时才有权重，而且所有附加通道总权重不超过0.20。最后严格选择32帧，并按时间连续性整理为局部证据包交给回答模型。

## 核心步骤

1. 将原问题对每帧的相似度做稳健标准化，得到概率分布；
2. 用“直接相关性 + 局部视觉时间覆盖”的单调次模目标选帧；
3. 只对问题明确许可的时间关系建立附加证据流；
4. 根据检索峰显著性平方校准权重，拒绝低可信Planner输出；
5. 在固定32帧预算下贪心优化，理论代理目标具有经典的 `(1-1/e)` 近似保证；
6. 不改变已选帧，仅把时间相近、角色一致的帧组成证据包。

## 全量实验

| 数据集 | 题数 | 分数 |
|---|---:|---:|
| Video-MME | 2700 | 63.33 |
| LongVideoBench | 1337 | 61.56 |
| MLVU | 2174 | **69.41** |
| LVBench | 1549 | 45.51 |

MLVU同协议下，Uniform 62.44、FOCUS 66.94、AKS 67.41、BOLT 68.03、Top-K 68.19，EviLoom为69.41。这里的结论是“在本项目统一的LMMS-Eval协议中领先已完成基线”，不是声称复现或击败了每篇论文的原始端到端系统。
